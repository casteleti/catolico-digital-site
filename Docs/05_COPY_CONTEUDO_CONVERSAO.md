# 05 — Copy, conteúdo e conversão

## 1. Regra central
A copy deve explicar valor antes de explicar tecnologia.

Evitar:
- “solução inovadora”;
- “revolucionário”;
- “ecossistema completo” sem evidência;
- jargão técnico desnecessário;
- promessas não verificáveis.

## 2. Hierarquia de mensagem
Cada página deve responder rapidamente:
1. O que é?
2. Para quem é?
3. O que resolve?
4. O que muda na prática?
5. Como funciona?
6. Por que confiar?
7. O que fazer agora?

## 3. Hero
Obrigatório:
- H1 específico;
- subtítulo;
- CTA primário;
- CTA secundário opcional;
- visual do produto ou contexto;
- microcopy de risco reduzido quando verdadeira.

Exemplo de estrutura, não copy final:
```text
H1: benefício principal + público
Sub: como o produto gera o benefício
CTA: ação concreta
Microcopy: condição real de teste/cancelamento/implantação
```

## 4. Dor
Não exagerar sofrimento.
Usar dores operacionais verificáveis:
- informação dispersa;
- atualização manual;
- dificuldade de comunicação;
- dependência de terceiros;
- presença digital desatualizada;
- trabalho repetitivo;
- baixa visibilidade de informações;
- dificuldade de manter canais atualizados.

## 5. Benefícios
Conectar recurso -> tarefa -> resultado.

Formato:
```text
Recurso: agenda centralizada
Tarefa: atualizar horários uma vez
Resultado: reduzir divergência entre canais
```

## 6. Prova
Aceitável:
- número real de clientes;
- caso real;
- depoimento autorizado;
- demonstração;
- captura real;
- tempo de mercado da equipe;
- integrações verdadeiras;
- documentação de segurança.

Nunca inventar:
- métricas;
- clientes;
- logos;
- resultados;
- depoimentos.

## 7. CTA
CTAs devem descrever a ação:
- “Ver demonstração”
- “Criar minha conta”
- “Entrar na lista”
- “Conhecer os planos”

Evitar CTA genérico repetido como “Saiba mais”.

## 8. Formulário
Reduzir campos.
Primeira conversão:
- nome;
- email;
- organização, se necessário;
- contato opcional;
- campo de necessidade opcional.

Explicar:
- por que a informação é pedida;
- como será usada;
- consentimento separado para marketing quando aplicável.

## 9. FAQ
Responder objeções reais:
- para quem é;
- preço;
- implantação;
- domínio;
- conteúdo;
- suporte;
- cancelamento;
- segurança;
- dados;
- integrações;
- propriedade do conteúdo;
- migração.

## 10. Conteúdo para SEO/AEO/GEO
Cada artigo:
- pergunta/problema central;
- resposta curta logo no início;
- contexto;
- passos;
- exemplos;
- limitações;
- FAQ;
- fontes quando aplicável;
- autor e data de revisão.

## 11. Tom
- humano;
- respeitoso;
- sóbrio;
- acessível;
- sem excesso de linguagem promocional;
- adequado ao universo institucional/religioso sem caricatura.

## 12. Microcopy
Criar microcopy para:
- erro de formulário;
- sucesso;
- consentimento;
- checkout;
- loading;
- vazio;
- 404;
- 500;
- newsletter;
- cancelamento.

Nunca deixar texto técnico de erro chegar ao usuário.
